# 素酒 · AI Studio 浏览器扩展（实验性）

此目录属于 Sujiu 仓库，保留独立的浏览器适配层，不修改 Rust 核心、HarmonyOS、Android 或 Qt 应用。支持 Chrome / Edge Manifest V3 扩展及 Tampermonkey 油猴脚本，两者从同一份源码构建。

## 功能

- 内嵌 Shadow DOM 面板：一个系统提示词编辑框，对应 AI Studio 原生 System Instructions；独立的压缩摘要模板，以及本地预设新建、切换、删除和 JSON 导入导出。
- 可把单段系统提示词写入 AI Studio 原生 System Instructions，或选择自动同步；页面编辑器不可访问时可复制后粘贴。系统提示词不会每轮追加进用户聊天历史，操作后请检查 Google 是否保存。
- 手动全历史摘要：让模型读取当前聊天的**全部已完成历史轮次**（包括最近 N 轮）及摘要指令，生成截至最新剧情的长期记忆；保留 N 轮仅用于之后的独立手动清理，最近 N 轮原文始终保留。
- 保留轮数由客户端按完整“用户消息 → 模型回复”划分，默认 8 轮。摘要发送不删减原生请求内容；如无法核对私有 RPC 的轮次结构，则拒绝自动摘要，普通聊天原样运行。
- 「生成摘要」「读取已完成摘要」「直接清理旧历史」互相独立；清理时按本地保留轮数选择旧历史，保护已标记的记忆和最近 N 轮，用户确认后通过原生菜单删除。只支持手动操作，不新建会话。

## 安装与验证

需要 Node.js 20+。在 apps/browser-extension 目录运行：

1. npm run check
2. Chrome / Edge 打开 chrome://extensions，启用开发者模式，加载 dist/extension 目录。
3. **油猴最简安装：** 直接打开 [最新版 sujiu-aistudio.user.js](https://raw.githubusercontent.com/Xiwei753/sujiu/feat/aistudio-browser-extension/apps/browser-extension/sujiu-aistudio.user.js) 导入 Tampermonkey，或复制其完整内容粘贴到一个新脚本；不需要拼接 src/ 目录。已有旧版请先停用，避免重复注入。构建产物 `dist/sujiu-aistudio.user.js` 与该直接安装文件由同一脚本生成。
4. **Chrome / Edge 新版必须检查用户脚本权限：** 浏览器扩展管理页 → Tampermonkey →「详情」→ 开启「允许用户脚本（Allow User Scripts）」。这个开关关闭时，脚本可以显示为已导入、已启用，但不会在网页执行。参考 [Tampermonkey FAQ](https://www.tampermonkey.net/faq.php?ext=dhdg&q=Q209&version=5.1.0)。
5. 打开 https://aistudio.google.com/prompts/new_chat 并强制刷新；也兼容旧的 /app/prompts/* 路径。首次安装后工具面板默认展开，此后通过右下角「素酒工具」开关。
6. 「生成摘要」和「读取已完成摘要」可独立使用；「直接清理旧历史」不要求新摘要或永久记忆标记。按最近保留轮数计算删除数量，确认后原生逐条删除，Google 页面自行保存。建议重要聊天先确认摘要完整，首次用测试聊天验收。

### 面板未出现时的最小诊断

在 AI Studio 标签页按 F12 打开 Console，先输入 `window.__SUJIU_AISTUDIO_BOOT__`：

- 返回 `undefined`：用户脚本仍未注入（检查 Tampermonkey 是否对该标签页显示运行脚本数量、脚本启用状态、站点访问许可和「允许用户脚本」）。如果连最小启动标记都没有，排查方向属于浏览器/油猴注入权限。
- 返回 `{ phase: "error", error: "..." }`：脚本已注入，但内部模块报错。页面右下角应有可点击的红色错误按钮。
- 返回 `{ phase: "ready" }`：查看 `window.__SUJIU_AISTUDIO_RUNTIME__` 中的 `panelInitialized` 和 `errors`。如果初始化成功但按钮仍不显示，优先检查网页是否覆盖了 DOM。

v0.1.2 起 `@match` 覆盖 `https://aistudio.google.com/*` 全站路径、`@sandbox raw` 明确页面注入，并在执行模块代码前创建启动标记。UI 初始化与网络 RPC 相互隔离。

## 架构

- src/00-state.js：AI Studio 端的状态与配置。
- src/10-settings.js：本地压缩设置、事件桥接。
- src/20-network.js：网络请求监听；摘要时只核对任务标识和轮次，Google 原生请求内容不被改写。
- src/25-compaction-task.js：随机任务标记和本地保留轮数记录。
- src/28-request-scope.js：检查完整摘要请求是否包括全部历史，计算之后独立清理应保护的最近 N 轮。
- src/30-compression.js：压缩生命周期、单次原生发送操作。
- src/35-rounds.js：纯函数，按完整轮次计算历史删除范围与保留范围，不改变模型请求。
- src/40-history.js：读取、解析 Google 保存的当前会话并校验摘要。
- src/50-branching.js：仅保留当前会话 ID 定位，不再创建新会话。
- src/55-in-place.js：独立手动旧历史清理，按当前 DOM 计算目标并保护近期消息和标记记忆；原生逐项删除。
- src/60-native-ui.js：原有工具栏按钮与页面适配。
- src/65-performance.js：可逆的模糊与平滑滚动性能优化。
- src/67-save-monitor.js：监听原生 UpdatePrompt 返回状态，不发送写请求。
- src/67-save-monitor.js：被动监听原生 UpdatePrompt 保存响应，并在批量删除后等待最后一次原生保存完成。
- src/70-utils.js：会话记录序列化辅助。
- src/75-prompt-profiles.js：单段系统提示词预设，旧版五段预设合并迁移和输入校验。
- src/80-prompt-panel.js：素酒提示词侧栏，独立 Shadow DOM。
- src/90-bootstrap.js：初始化。
- scripts/build.mjs：同一源码构建 MV3 和油猴脚本。
- tests/：纯逻辑自动化测试。

这些文件仍处于同一个打包后的 IIFE 作用域，暂时沿用上游的内部结构，避免在首轮移植时同时重写未公开 RPC 协议。模块边界首先按职责划开，后续可以逐步收敛为显式依赖接口。

## AI Studio Trusted Types 兼容性（v0.1.3）

AI Studio 的内容安全策略可能要求所有 HTML 解析操作使用 `TrustedHTML`。v0.1.2 及更早版本尝试通过 `shadow.innerHTML` 构建侧栏，会被浏览器拒绝，表现为网络拦截已经启动而「素酒工具」悬浮窗完全不出现，控制台有 `This document requires 'TrustedHTML' assignment`。v0.1.3 改用 `createElement`、`append`、`textContent`、`setAttribute` 逐个创建 DOM，不申请任何 Trusted Types 绕过策略；并增加在禁止写入 `innerHTML` 的模拟环境下验证面板成功挂载的测试。油猴和 MV3 均通过同一构建入口打包。

## 原地删除风险

**重要：原地压缩没有完整原始会话的自动备份，删除不可撤销。** 插件通过逐条点击 AI Studio 当前 UI 的原生删除菜单，不修改私有的 Drive 存储结构，不会静默篡改模型请求中的思考签名。与 QuickNav 等脚本类似，浏览器 DOM 结构变化可能导致中途终止；如果已经部分删除，必须刷新确认剩余历史。第一次只能在测试会话执行。若当前页面并未加载完整历史，插件直接拒绝执行以避免错误地选择范围。

## 压缩发送行为（v0.2.1）

压缩摘要只允许一次原生运行按钮点击。旧实现会在 1.8 秒未捕获到请求时再次模拟点击，若 AI Studio 已将「运行」切换为「停止」，就可能反向终止生成。新版取消重复点击、合成指针事件、键盘发送回退和强制启用按钮；遇到不可用按钮或未捕获网络请求只提示状态，不自动重发。此修复不改变摘要生成后手动确认原地删除的流程。

## 两阶段手动压缩（v0.2.2）

摘要生成与读取、清理彻底分开，所有步骤由用户手动启动。启动摘要发送后，网络请求与响应监听**不设置固定的 12 秒、20 秒或其他等待超时**，直到生成事件完成、用户选择「停止插件监听」、或页面卸载。即使插件没有捕获到请求，也可以在 AI Studio 显示模型回复全部完成后点击「读取已完成摘要」，通过 `ResolveDriveResource` **重新读取 Google 已保存的最新会话**，并确认最后一对消息确实是素酒发出的摘要指令和模型回复；在验证失败时不会开启删除预览。

v0.2.1 的 XHR 拦截路径中遗漏了生成请求事件的 `bodyText`，使监听器无法识别已发送的摘要请求；v0.2.2 已修复这一字段丢失。「停止插件监听」只关闭素酒监听，不会点击 Google AI Studio 的停止按钮，更不会停止模型生成。历史消息依旧只在读取摘要且再次显式确认后删除。

## 已淘汰：旧历史请求隔离（v0.3.0）

保留最近 N 轮是**客户端操作**。脚本给本次摘要请求附加唯一标识，随后在真正发送 GenerateContent 之前，把请求历史划分成「较早轮次」和「最近 N 轮」，仅将较早轮次及摘要指令放入模型请求。请求中没有「保留 N 轮」指令，摘要提示词只讨论实际提供的历史与事件时间线。截取失败时必须拒绝发送，绝不能退化为发送全部历史。

新任务会在页面的 localStorage 保存任务标识、保留轮数、裁剪已核对的布尔标识及裁剪前总轮数，不保存原始对话。恢复摘要时重新读取云端历史，核验最后一条用户消息是当前任务，及其后有可见模型回复；历史轮数不符或未经裁剪的旧任务不允许进入删除阶段。

删除依赖 AI Studio 原生 `ms-chat-turn` 组件的真实 DOM，参考 [QuickNav for Google AI Studio](https://greasyfork.org/en/scripts/548346-quicknav-for-google-ai-studio/code) 的分类和 Angular CDK 菜单选择器。逐条删除旧轮次，关联思考节点包含在范围内；最近 N 轮和摘要必须保留。执行前再次核对云端原始轮数及 DOM 历史数量。任何单项失败将停止后续删除并显示具体错误，人工刷新确认实际保存结果。

**尚未在你的登录态 Edge 中完成实际验收。** Google 可能将改写后的生成请求作为当前会话保存输入，若破坏了原始历史，回读校验会停止删除，但不能挽回原生应用自己的改动。请只用一次性测试会话验证此版本，不要拿长期连载聊天第一次尝试。

## 页面卡顿与云端保存诊断（v0.3.1）

**长会话卡顿：** 插件内新增可关闭的「减少页面特效（模糊与平滑滚动）」开关，默认启用，参考 [xgloom/fix-aistudio-lag](https://github.com/xgloom/fix-aistudio-lag)。通过页面 CSS 关闭 `backdrop-filter` 和平滑滚动，减少 GPU 重绘；可随时关闭恢复。它不会从 DOM 移除历史消息，也不会阻止 AI Studio 自身的 CountTokens 请求，因此对特别长的聊天只能缓解部分卡顿。插件不再为了提速去删/藏消息。

**Google 云端保存：** 2026 年 Google AI Studio 依赖自动保存，原生聊天菜单的删除可能只更新了浏览器里的数据，刷新后恢复。v0.3.1 被动观察 `UpdatePrompt` 返回状态；状态和计数会出现在 `window.__SUJIU_AISTUDIO_RUNTIME__.save` 中，且不记录任何请求正文/密钥。v0.3.1 曾在每轮删除后回读服务器；v0.3.2 曾在批量删除后统一回读；v0.3.3 曾尝试寻找额外保存按钮；v0.3.4 已恢复由原生删除菜单触发 Google 自动保存，只等待批次末尾的 UpdatePrompt 响应，不主动再次保存。若没观察到更新或 Google 端内容仍未变化，会明确报告失败并停止，**不再将 DOM 删除等同成功**。

**此版仍没有已验证的强制上传能力。** 不能为了“修复保存”盲目重放 `UpdatePrompt`，因为它使用未公开的私有协议，格式不明会有损坏会话的风险。要进一步实现真正原地云端保存，需要先获取 AI Studio 自身正常保存一条修改时的合法调用格式并在测试会话验证。当前保留这一块为未完成的功能。

## 压缩记忆标记与批量清理（v0.3.2）

摘要生成时要求模型在**可见回复的第一行**原样输出 `[[SUJIU_MEMORY_V1:任务ID]]`。只有 Google 已保存的模型回复确实包含对应标识，才允许开启不可逆的清理；标识随摘要正文存储在 Google 会话中，重新打开或再次压缩时也能识别。较早历史中已标记的压缩摘要会列入保护名单，不参与删除。旧版没有这一标记的摘要不能自动推断为可保护记忆，需要重新生成有标记的摘要。

清理计划只选择普通较早轮次；已经有标记的旧摘要整轮保留。新产生的摘要回复本身**绝不加入删除队列**；发送给模型的临时工具提示和能够独立删除的对应思考块可以进入队列。若思考内容和摘要回复共用不可分离的 UI 组件，跳过该思考块，优先确保摘要不丢失。删除任意消息后还会检查页面上保护的内容是否仍在，若原生删除有联动导致它消失，立即停止。

**批量执行，末尾保存：** 用户确认后依次调用 AI Studio 原生消息菜单，完成后只尝试一次原生「保存」动作。请注意：原生 AI Studio 仍可能**自行**在单次删除后自动保存，脚本不控制它发送多少次 `UpdatePrompt`。这版不能保证所有模型、DOM 结构和 Google 私有保存格式都兼容，首次仍须在可丢弃的测试会话中验证，尤其关注删除工具提示是否连带删除摘要回复。

## 压缩模板与原生自动保存（v0.3.4）

默认摘要提示词参考 [SillyTavern Summarize](https://docs.sillytavern.app/extensions/summarize/) 和 [OpenCode Compaction](https://dev.opencode.ai/v2/docs/compaction/) 的长期记忆设计，扩展为通用、可审查的结构化总结。重点分别记录：历史范围、稳定设定、人物与关系、关键事件时间线、状态变更、承诺与目标、未决线索、**仅截至提供历史末尾的状态**、连续性容易误判之处。明确区分过去阶段的“当时状态”与已完成结果，旧记忆作为历史依据与后续修改合并，保持证据界限。最近保留 N 轮依旧在客户端裁剪，不进入摘要指令。旧版内置默认会迁移；用户主动编辑的摘要提示词保持原样。

执行清理前仍要确认目标范围，以防不可撤销误删。确认后批量调用 AI Studio 原生消息删除菜单，每次菜单删除由 Google 页面自身决定何时自动保存（通常是 `UpdatePrompt`）；整个批次结束后等待最后一次原生删除之后的自动保存响应。**插件不调用额外的「保存」按钮，也不自行构造任何 `UpdatePrompt` 请求**。此前所谓「逐条保存」实际上是逐条删除后通过 `ResolveDriveResource` 读取云端检查，属于读取操作，并不是写入。现在不再逐条回读服务器，仅被动观察现有的原生自动保存响应；返回 200 表示保存请求得到成功响应，仍建议在保存结束后刷新核对。

## 摘要与历史清理分离（v0.3.5；v0.3.6 进一步修正摘要范围）

「生成摘要」只发送旧历史并等待模型回复；「读取已完成摘要」只用于查看、检查该摘要；「直接清理旧历史」是**始终可点击的独立动作**，不需要先生成摘要，不需要有素酒压缩标记，也不会调用 `findSavedSummary` 或检查当次摘要任务。它直接依据当前页面可见的原生完整对话轮次和「保留最近完整轮数」计算删除范围，点击后再次显示删除数量以供用户确认，随后通过 AI Studio 原生菜单删除、由 Google 页面自行触发自动保存。

对话与压缩记忆分开计数：带有工具任务标识及压缩记忆标识的摘要轮次不占用最近 N 轮普通对话名额；旧历史里包含已标记压缩记忆的完整轮次也会受到保护。没有记忆标记的旧文本无法被自动识别为摘要，可能随其他旧历史一起删除，因此请在手动清理前确认其价值。客户端仍验证消息角色、DOM 稳定性、目标菜单和最近 N 轮的保护范围，防止选择范围偏移；这些检查**不依赖摘要内容或云端回读是否识别成功**。Google 端的自动保存仍是原生应用行为，操作完成后可刷新检查。

## 全历史压缩与近期原文保留（v0.3.6）

**摘要范围与删除范围分别计算。** 假设已有 94 个完整轮次且设置保留最近 20 轮：模型收到完整的 94 轮历史以及摘要指令（此前版本错误地只发送前 74 轮）；生成的摘要覆盖全部 94 轮，能反映最后一轮的剧情和状态。之后用户单独点击「直接清理旧历史」时，插件才会选择更早的 74 轮进行删除，最近 20 轮的原文、带永久标记的旧压缩记忆和新摘要受到保护。工具产生的摘要轮次不挤占最近 20 轮普通对话的计数。

摘要请求原样传递给 AI Studio，不再序列化、裁剪或修改 Fetch/XHR 的请求体。客户端只检查摘要任务标识、请求的完整轮次与之后保留 N 轮的划分。新任务本地记录 `fullHistoryVerified`；旧版本的 `scopeVerified` 不再代表正确的全历史摘要。内置压缩提示词也已更新为记录**全部已提供历史的末尾状态**，而非“只截至最近保留轮次之前的时间”。用户编辑过的自定义提示词不被覆盖。

## 单段系统提示词与旧预设迁移（v0.4.0）

提示词预设只提供**一个「系统提示词」编辑框**。可以切换预设、手动注入 AI Studio System Instructions，或在用户开启自动同步后将当前预设写入原生系统指令框。插件不会把每段设定反复拼入用户聊天消息；系统指令是否成功同步仍由 AI Studio 原生页面控制。

「压缩摘要提示词」保持独立，只有用户手动点击生成摘要时才使用。上下文清理、性能开关及此前的永久压缩记忆机制不变。

首次运行 v0.4.0 时，将老 `sujiu:aistudio:prompt-presets:v1/v2` 中的每个预设按**原来的启用状态和排列顺序**合并为一段文本，保留旧有章节标题，避免改变既有提示词的含义。禁用段落不注入系统指令，但会保留在新预设的 `legacyDisabled` 数据中，JSON 导出可取回；原始 v1/v2 存储仍保留，并额外备份到 `sujiu:aistudio:prompt-presets:backup:v2`。新格式使用 `sujiu:aistudio:prompt-presets:v3`；重复刷新不会重复合并。已有 v3 预设不会被旧数据覆盖。

## 已知限制与安全边界

- Google AI Studio 使用未公开的内部 RPC，索引位置和页面选择器会变。当前无法在用户的登录态浏览器里实测，因此这是**待验收的初版**，请勿当作稳定功能。
- 摘要通过 AI Studio 原生 GenerateContent 发送完整聊天历史；保留最近 N 轮只用于手动删除时筛选范围。脚本不会裁剪模型请求里的近期原文。
- 当前会话重新读取使用 Google 会话 Cookie 派生认证头及从原生请求捕获的 API Key，密钥只在当前页面内存使用，不写入日志或用户预设备份。
- 提示词预设保存在站点 localStorage 中，适合普通设定，不建议写入私密密钥。
- 当前会话将先追加一次总结消息和模型摘要回复。确认后会**不可逆地删除原聊天较早轮次（包括其思考内容）**，并保留最近完整轮次及摘要。不会生成新的会话 URL。没有自动删除或自动压缩。
- 20 万 tokens 是建议的**手动检查时间点**，不是兼容所有模型的统一阈值；当前没有实现可靠的实时 token 计数，请以 AI Studio 显示的用量及模型限制为准。
- 用户脚本必须以页面上下文运行（@grant none）；Manifest V3 使用 world: MAIN。两者均只匹配 AI Studio 站点；UI 可在首页显示，压缩仅用于聊天页。

## 验收场景

准备 60 个已完成轮次，选择保留 8 轮。摘要生成后先预览，确认删除范围为第 1–52 轮，连同其关联思考块；原始最近 8 轮和摘要轮次保留。执行前检查原会话保存结果和浏览器 DOM 轮次一致，任何未加载、角色未知或 ID 缺失都拒绝删除。刷新后地址不变，下一次 GenerateContent 请求不再含旧 52 轮的完整内容。**没有在真实登录态验证前，切勿在重要会话使用破坏性清理。**
